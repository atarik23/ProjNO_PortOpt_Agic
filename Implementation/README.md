# Mean-Variance Portfolio Optimizer

Course project for **Numerical Optimization**.

**Author:** Tarik Agić (20108)

The application solves long-only mean-variance portfolio optimization problems, constructs the efficient frontier, and visualizes how optimal portfolio weights change with the target return. The graphical interface and matrix backends use the professor's **natID framework**.

## Optimization problem

For an estimated mean-return vector \(\mu\), covariance matrix \(\Sigma\), and target return \(r\), the application solves

\[
\begin{aligned}
\min_w \quad & \frac{1}{2}w^T\Sigma w \\
\text{subject to} \quad
& \mu^T w = r, \\
& \mathbf{1}^T w = 1, \\
& w \geq 0.
\end{aligned}
\]

The non-negativity constraints enforce a long-only portfolio. An asset belongs to the active set when its bound is active, meaning \(w_i = 0\).

## Active-set algorithm

The solver starts from a feasible long-only portfolio and maintains a working set of active zero-weight bounds.

At each iteration, it:

1. constructs the equality-constrained KKT system;
2. solves for a feasible search direction;
3. moves toward the unconstrained minimizer until another bound blocks the step;
4. adds the blocking constraint to the active set; or
5. removes an active bound whose multiplier violates the optimality conditions.

The process stops when the search direction is negligible and all active-bound multipliers satisfy the KKT conditions.

A small covariance regularization is used internally to improve numerical stability. Reported portfolio risk and variance are calculated using the original sample covariance matrix.

## natID matrix backends

The application supports two professor-provided matrix implementations:

- `dense::DblMatrix`
- `sparse::DblSolver` with general LU factorization

Both backends solve the KKT systems generated by the same active-set algorithm.

The GUI can run the same target-return problem through both backends and report:

- active-set iterations;
- number of active constraints;
- maximum absolute difference between portfolio weights;
- variance difference;
- budget-constraint residual;
- target-return residual;
- single-run execution time.

The displayed execution time is informational and should not be interpreted as a rigorous performance benchmark.

## Expected input format

The input is a CSV matrix of periodic asset returns. Return values must be decimals, so `0.012` represents `1.2%`.

Example:

```csv
Period,Asset A,Asset B,Asset C
2026-01,0.012,0.004,-0.003
2026-02,-0.006,0.008,0.011
2026-03,0.009,-0.002,0.006
```

The first column is optional. It is interpreted as an observation label when its header is one of:

- `Date`
- `Period`
- `Time`
- `Timestamp`
- `Observation`

All remaining columns represent assets. Every asset must contain the same number of finite numeric observations.

A synthetic five-asset sample is bundled with the application.

### Real-market sample

The application also includes a real-market sample containing monthly returns for five exchange-traded funds: SPY, QQQ, IEF, LQD, and GLD.

The dataset contains 72 monthly observations from January 2020 through December 2025. The original ticker symbols are preserved.

Monthly returns were derived from daily adjusted-close data by selecting the final available trading observation in each calendar month and computing

\[
r_t = \frac{P_t}{P_{t-1}} - 1.
\]

The adjusted-close source subset is included as `res/data/real_market_adjclose_source.csv`, while the derived optimizer-ready dataset is included as `res/data/real_market_returns.csv`.

The source data originates from the public [manisahni/marketdata](https://github.com/manisahni/marketdata) dataset. The real-market sample can be loaded directly from the **Return Data** tab using **Load Real Market Sample**.

## Application workflow

1. Open the **Return Data** tab.
2. Load a CSV file, select **Load Synthetic Sample**, or select **Load Real Market Sample**.
3. Open the **Portfolio Explorer** tab.
4. Set a feasible target return using the precise input or synchronized slider.
5. Select **Optimize Target** to solve a single long-only portfolio.
6. Select **Build Efficient Frontier** to construct a family of optimal portfolios.
7. Explore representative frontier solutions using **Minimum Risk**, **Balanced**, and **Highest Return**.
8. Inspect the selected portfolio's expected return, risk, variance, allocation, active-set iterations, and active constraints.
9. Use the **Efficient Frontier**, **Selected Allocation**, and **Portfolio Weights** tabs for detailed visual analysis.
10. Optionally select the dense or sparse natID matrix backend and compare their numerical solutions.
11. Export the efficient frontier or portfolio-weight data to CSV.

The three portfolio landmarks are navigation aids over already computed efficient-frontier solutions. They are not financial recommendations.

Target returns use the same periodic scale as the loaded data.

### Portfolio Explorer

The Portfolio Explorer is the central workspace for selecting and inspecting an optimized portfolio. User-facing portfolio controls and results are presented separately from lower-level numerical information.

The selected-portfolio summary reports expected return, risk, variance, and asset allocation. Numerical optimization details expose the selected natID matrix backend, active-set iteration count, and active zero-weight constraints.

After the efficient frontier has been constructed, **Minimum Risk**, **Balanced**, and **Highest Return** select the first, middle, and final sampled frontier solutions, respectively. Selecting a landmark synchronizes the target-return controls and the visualizations without introducing a separate optimization model.

## Exported CSV format

The exported frontier contains one row per optimized portfolio and includes:

- target return;
- achieved expected return;
- risk;
- variance;
- active-set iteration count;
- number and names of active constraints;
- weight of every asset.

All numeric return and weight values are exported as decimals rather than percentages.

## Prerequisites

- Windows 10 or Windows 11
- Visual Studio 2022 with C++ desktop development tools
- CMake 3.18 or newer
- natID SDK 4.2.1
- 64-bit build configuration

By default, the SDK is expected at:

```text
%USERPROFILE%\natID.SDK
```

A different SDK location can be supplied through the CMake variable `NATID_SDK_ROOT`.

## Command-line build

Place the project at:

```text
%USERPROFILE%\ProjNO_PortOpt_Agic\Implementation
```

Configure the Visual Studio solution:

```bat
cmake -S "%USERPROFILE%\ProjNO_PortOpt_Agic\Implementation" -B "%USERPROFILE%\natID.RAMDisk\build\ProjNO_PortOpt_Agic" -G "Visual Studio 17 2022" -A x64
```

Build the Debug configuration:

```bat
cmake --build "%USERPROFILE%\natID.RAMDisk\build\ProjNO_PortOpt_Agic" --config Debug
```

## Running automated tests

Make the natID runtime libraries available:

```bat
set "PATH=%USERPROFILE%\natID.SDK\bin;%USERPROFILE%\natID.SDK\bin\GTK;%PATH%"
```

Run the tests:

```bat
ctest --test-dir "%USERPROFILE%\natID.RAMDisk\build\ProjNO_PortOpt_Agic" -C Debug --output-on-failure
```

The automated test suite covers:

- CSV parsing and validation;
- sample mean and covariance calculation;
- analytical two-asset optimization;
- global minimum-variance optimization;
- active non-negativity constraints;
- KKT-condition validation;
- infeasible target rejection;
- malformed CSV rejection;
- efficient-frontier feasibility;
- dense and sparse backend agreement;
- larger 20-asset systems;
- a correlated positive-definite 20-asset covariance matrix.

## Scope

The implemented model assumes:

- long-only portfolios;
- full investment of available capital;
- no transaction costs;
- no taxes;
- no explicit risk-free asset;
- historical sample estimates for expected returns and covariance;
- a single-period mean-variance model.

These assumptions keep the implementation focused on the numerical optimization model and its computational solution.
